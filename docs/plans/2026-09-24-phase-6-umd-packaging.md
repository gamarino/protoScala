# protoScala Phase 6 — UMD, Modules, the Precompiled Prelude and Packaging Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a polyglot, installable runtime (ROADMAP "Phase 6"): `ScalaModuleProvider` loads `.scala` modules and registers with protoCore's `ProviderRegistry` so another runtime can import a protoScala module; `import` stops being parsed-and-ignored and becomes a real binding form, with the `py.`, `js.`, `st.` and `clj.` prefixes routing to their providers; the boundary catch shape of protoST's mandatory §6 is installed at every UMD and foreign-call site; the prelude stops being parsed, desugared, compiled and run at every start-up, which reclaims DESIGN §1's `< 25 ms` cold-start budget; the packaging half of the done-when is closed by the two items the installer phase left (a `.tar.gz` and a package at the current version); and the documentation track delivers its final instalment — tutorial chapter 15, the worked example, and a "protoScala in 10 minutes" section per audience. Release **0.6.0**.

**Architecture:** Three mechanisms, one of which is smaller than the ROADMAP implies and one of which is larger.

*Imports resolve at compile time, through a `ModuleLoader` seam.* The compiler gains a `ModuleLoader*`; an `Import` node asks it to load a module and returns plain C++ descriptors (`ModuleExports`: a term key, a type key, member bindings, `ClassInfo`s) — **no `ProtoObject*` ever reaches the compiler or the AST** (DESIGN §3.3). `Session` implements the loader, because it is what owns the `ProtoSpace`, the engine and the globals. This is the one place in the dialect that binds *early* rather than late, and it is deliberate: a Scala programmer imports **types** (`import util.Shapes.Point` then `case Point(x, y) =>`), and a name bound at run time carries no `ClassInfo`, so `new Point(1, 2)` and `case p: Point` would not compile. Following Scala here costs a seam; not following it costs a common usage.

*A protoScala module is an `object`.* `desugarModule` wraps a module file's top-level statements in a synthetic `object <LastSegment>` and then runs the ordinary desugarer, so **Phase 4's nested-template lifting does all the work**: `util/Shapes.scala` becomes `object Shapes { … }`, its classes are lifted to the qualified names `Shapes.Point` with their companions, its `def`s become members, and `import util.Shapes` binds one name to a lazy singleton the import site forces. `import util.Shapes.{Point, area}` binds a **compile-time alias** — a name that rewrites to the same member access `Shapes.area(…)` the qualified spelling compiles to. No new resolution rule, no new opcode, no new runtime object model.

*Prefixed imports are dynamic, because the foreign world is.* `import py.numpy as np` strips the prefix, asks `ProviderRegistry::instance().getProviderForSpec("provider:py")` and calls `tryLoad("numpy", ctx)` directly — **not** through `ProtoSpace::getImportModule`, so the process-global `SharedModuleCache` (keyed by logical path with no `ProtoSpace` component) is not consulted for a foreign path and cannot hand a protoScala program a module some other runtime loaded under the same name. The unprefixed path *does* go through the resolution chain, with `provider:scala` first. A foreign module object is bound as an ordinary `Val`; its members resolve by name at run time, exactly as DESIGN §5's type-mapping table says ("other objects → dynamic objects").

*The prelude becomes a build product, not a cache.* A host tool `protoscala-precompile` compiles `lib/prelude.scala` at **build** time and emits `PreludeImage.cpp` — static tables for the code words, the constant pool, the handler tables, the block tree, the `GlobalTable` bindings and the `ClassInfo`s — plus `buildPreludeImage()`, which materialises them with no lexer, no parser, no desugarer and no compiler in the path. Because the image is generated by an `add_custom_command` that `DEPENDS` on `lib/prelude.scala`, **it cannot go stale**: there is no cache directory, no mtime comparison and no run-time hash of a 10 KB source. A format-version byte and an FNV-1a-64 of the prelude source are baked into the image and checked at start-up against the value baked into the *embedded source* constant, so a hand-edited or hand-copied image falls back — loudly, on stderr — to the source path that ships beside it. What the image cannot remove is the *run* phase (`MAKE_CLASS`, `MAKE_FN`, `STORE_GLOBAL`); Task 1 measures the split **before** Task 2 builds anything, and E5 says what happens if the run phase turns out to dominate.

*Packaging is nearly done already* (see "What the installer phase already delivered", below) and is one task, not a phase.

**Tech Stack:** C++20, CMake ≥ 3.20, protoCore ≥ 2.1.0 (`find_package(protoCore 2.1 CONFIG)`, sibling-tree fallback `../protoCore/build_release`), GoogleTest 1.14, libreadline, `dlopen`/`dlsym` (POSIX, for the provider plug-in mechanism; `LoadLibrary` is out of scope — Windows is UNVERIFIED for packaging already); Python 3 for `benchmarks/run_benchmarks.py`; Scala 3.9.0 at `/home/gamarino/Documentos/proyectos/tools/scala3-3.9.0` (`bin/scalac` plus `java -cp "$SCALA_HOME/lib/*:out"`, **never** `bin/scala`) as the reference for expected outputs; OpenJDK 21 for that reference only; `dpkg`/`dpkg-deb` and `tar` for the packaging task.

**Spec:** `docs/DESIGN.md` §1 (the `< 25 ms` budget), §1.1 (P1–P6), §3 (the pipeline, which already draws `ScalaModuleProvider`), §3.1 (`src/umd/`), §3.3 (the AST holds no `ProtoObject*`), §3.5 (opcodes and their bands), §4.5 (templates), §4.6 (the `ProtoTuple` prohibition), §5.2 (named and default arguments), §7 (the native-error translation table, whose last row is *this* phase), **§9 (Modules and polyglot interop)**, §10 and §10.1 (testing and documentation), §11 (R4, **R5**, R8); `docs/ROADMAP.md` "Phase 6" and the Documentation track's final deliverable; `docs/INTEROP.md` (the whole document, **§7** in particular); `docs/LANGUAGE.md` §1 (`import`); `docs/STATUS.md` (D1–D89, the opcode table, "Not yet implemented"); `docs/plans/2026-09-23-phase-i-installers.md` (what packaging already ships); `protoST/docs/archive/design-specs/2026-05-20-exceptions.md` §6 (the mandatory boundary shape) and `protoST/src/modules/STModuleProvider.{h,cpp}` (the provider and the space-keyed registry this plan copies rather than invents); `protoPython/src/library/PythonModuleProvider.cpp` and `CompiledModuleProvider.cpp` (the second provider precedent, and the `dlopen` precedent).

**Binding principles (DESIGN §1.1 P1–P6).**

- **P1 — values live in protoCore structures.** Two new places matter in this phase. (a) The module table (`src/repl/ModuleTable.h`) keeps a `std::map<std::string, LoadedModule>` whose `LoadedModule::object` is a `ProtoObject*`. That is legal here **because the same object is also the value of a session global** in `L.globals`, which is pinned in a root-context slot: the map is a lookup index over something already rooted through one pinned structure, never the only reference. Every entry is written into the globals object **before** it enters the map, and a code comment says so at the write. (b) A provider's `tryLoad` returns a `ProtoObject*` into protoCore, which roots it in `space->moduleRoots`; nothing on protoScala's side may hold it in a C++ local across an allocation.
- **P2 — one `ProtoContext` per invocation.** A module's top level runs in its own child context of the root context, created by the loader and destroyed when the load returns; the compiler that asked for it holds no context at all.
- **P3 — a missing capability extends protoCore as a new type.** Phase 6 needs **nothing new from protoCore**: `ModuleProvider`, `ProviderRegistry`, `setResolutionChain` and `getImportModule` all exist and are used as they are. **If an implementer concludes a protoCore change is required — and the prelude image is where that could happen, see E5 — that is a maintainer decision:** write it into Task 0 as a new `A0-n` with options and a recommendation, and stop. Never patch protoCore from this plan.
- **P4 — every deviation from Scala 3 is documented** with a stable id in `docs/STATUS.md`. **Phase 6 uses D90 onwards.** The highest id in use is **D89**; **D57, D60, D64 and D78 are deliberately unused** and are not to be recycled. **Re-check before writing a single id:** `grep -oE 'D[0-9]+' docs/STATUS.md | tr -d D | sort -n | tail -1` must report `89`; if it reports more, shift the whole D90–D96 block so it starts one past it, keep the relative order, and record the shift in `docs/DECISIONS-LOG.md`.
- **P5 — purity over performance.** The cold-start work of Tasks 1 and 2 is the one performance item in this phase and it is measured, not asserted: every figure comes from `benchmarks/cold-start.sh <binary> 21` with all 21 runs verified, and any claim about the *engine* is backed by `perf stat -r 3` cycles on a quiet host. A design that fragments protoCore's conceptual model to save a millisecond is rejected: that is why the prelude image is a protoScala build product and not a protoCore object-graph dump.
- **P6 — no mutable-heap GC premises.** No new stop-the-world work, no write barrier, no card marking. The module table's mutex is held only for the container operation, and any wait for another thread's in-progress load happens inside `proto::ProtoContext::UnmanagedScope` so the waiter is GC-parked (protoST's `importModuleFile` shape).

**`ProtoTuple` prohibition (DESIGN §4.6, R2).** **Never map transient data to `ProtoTuple`.** protoCore interns every `ProtoTuple` node and **interned tuple nodes are perennial** — never collected, never moved — so a transient mapped to one is retained for the life of the process. Scala tuples are the **case classes** `Tuple2`..`Tuple22` (Phase 2). In this phase the rule applies to: a module object (an ordinary mutable prototype-based object built with `newChild(ctx, true)`, exactly as protoST's `loadModuleFromFile` builds its); the resolution chain (a `ProtoList` of `ProtoString`, which is what `setResolutionChain` demands); the exports of a module (attributes of the module object); the keyword-argument bundle at a foreign call (a `ProtoSparseList` keyed by the **address** of an interned parameter-name symbol — INTEROP §7, and the one structure whose use of interning is correct *because* interned strings are perennial and so need no tracing); and the prelude image's tables (plain C++ PODs in generated `static constexpr` arrays, holding no `ProtoObject*` at all).

**`PROTO_NONE`.** `PROTO_NONE` is Scala `null` *and* "attribute missing" *and*, in the UMD contract, **"this provider does not have that module"**. `ModuleResolver.cpp:99` treats `nullptr` and `PROTO_NONE` identically as a miss, so `ScalaModuleProvider::tryLoad` returns `PROTO_NONE` for "not mine" and **never** raises for it. Presence of an attribute is probed with `hasOwnAttribute`/`hasAttribute` or by the `nullptr` a raw accessor returns, never by comparing a lookup result with `PROTO_NONE` alone — which is exactly how `bindForeignMember` must tell "the attribute is absent" from "the attribute is `null`".

**Interned symbols.** Symbols are per `ProtoSpace`. **Never cache them in function-local `static`s** — protoST's `prim_Import_from` carries the comment explaining why (a static binds to the first space and breaks in a multi-runtime process, which is precisely the process this phase creates). Every new attribute key and method name goes into `RuntimeLayout` (filled in `Runtime::Runtime`) and is read from there; the `"exports"` unwrap key of `getImportModule` is one of them. **Every keyword-argument key is derived from `proto::ProtoString::createSymbol`, never from `fromUTF8String`, `fromUTF8` or `fromStdString`**: protoCore embeds a short string in the pointer word, so a non-interned key works *by accident* for a short parameter name and fails silently for one too long to embed (INTEROP §7).

**The dual-audience tutorial rule (the Documentation track, every phase).** Phase 6 writes `docs/tutorial/15-modules-and-polyglot-interop.md` and `docs/tutorial/worked-example.md`, and extends `docs/tutorial/01-introduction.md` (installing from a package), `02-for-the-python-or-javascript-developer.md` (the bridge: Python's `import x as y` / `from m import a`, JavaScript's `import`/`require`, and how a protoScala module differs from both) and `03-for-the-scala-developer.md` (the departures catalogue, keyed to D90–D96). **The tutorial is dual-audience and both audiences are served in every chapter it touches:** a traditional Scala programmer gets an honest catalogue of departures keyed to the D-ids; a developer coming from Python or JavaScript gets the concept from first principles with a bridge back to what they know. **Every runnable snippet in a chapter is, verbatim, the body of a conformance fixture** `tests/conformance/tutorial/NN-<topic>-<name>.scala` whose `// EXPECT:` line is the output printed under the snippet, so the text cannot drift from the implementation. A snippet shown as failing is a fixture with `// EXPECT-ERROR:` and the quoted message is the one the binary prints.

**Conformance fixtures.** `tests/conformance/NN-topic/*.scala`; the **first line** is the directive and nothing else is parsed: `// EXPECT: <last non-empty stdout line>`, `// EXPECT-ERROR[: <substring of stderr or stdout>]`, `// XFAIL: …`, `// XFAIL-ERROR[: …]`. ## Task 0: Maintainer decisions

Each `A0-n` is settled here so no task has to decide while implementing. Items marked **ESCALATED** are in the triage table at the end and need the maintainer; every other item is decided, with the cost that decided it.

### A0-1 — When an import is resolved: compile time, and why this is the one early-bound form

**Decided: compile time, through a `ModuleLoader` seam the `Compiler` holds a pointer to.** The alternative (a `__import` native called from emitted bytecode, resolving at run time) is smaller — two natives, no seam — and it is what "the platform is late-binding" would suggest. It was rejected on what it costs the programmer: a name bound at run time carries no `ClassInfo`, so an imported class cannot be used as a **type** — `new Point(1, 2)`, `case p: Point`, `case Point(x, y)` and `x.isInstanceOf[Point]` would all be compile errors, and importing types is what a Scala programmer does with `import`. The standing rule is *follow Scala by default, bounded by proportionality*; here following Scala costs a seam and not following it costs a common usage, so the seam is paid.

The seam does **not** breach DESIGN §3.3: `ModuleLoader` returns plain C++ descriptors and the `Compiler` never sees a `ProtoObject*`. Late binding is preserved everywhere it is observable — a *member* of an imported module is still reached by an ordinary `SEND`, and a foreign module's members are resolved by name at run time (A0-4).

Two consequences are recorded as deviations rather than hidden: a module's top level runs **at import**, during the importing unit's compilation (**D90**), and `--disassemble` therefore runs the modules a file imports (**D95**).

### A0-2 — What a protoScala module *is*: an `object`

**Decided: a module file is desugared into a synthetic `object` named after its last path segment**, and the ordinary desugarer then runs. Phase 4 already lifts templates nested in an `object` to qualified names with their companions, resolves unqualified sibling references innermost-first, and shows the simple name while resolving the qualified one — which is every mechanism a module needs. `util/Shapes.scala` becomes `object Shapes`, its `case class Point` becomes `Shapes.Point`, its `def area` becomes a member, and `import util.Shapes` binds one lazy singleton.

The alternative (a bespoke "module" object model with its own member table) would be a second object model for something the first already expresses — the same reasoning that kept `enum` in the frontend in Phase 4. Recorded as **D91**, with its two visible edges: a module may not carry `@main` (the file is a library, not a program, and a silently ignored `@main` would be a trap), and the module's name is its **file name**, not anything written inside it.

### A0-3 — How the module object is initialised: forced at import

**Decided: the import site forces the singleton, so a module's top level runs when it is imported.** An `object` in Scala initialises on first access; a module in Python and in JavaScript runs at import. Nothing in Scala has file-level modules, so there is no Scala behaviour to match, and the audience that has modules expects them to run. Forcing also makes a module that exists for its effects (`import mylib.Setup`) work, which lazy initialisation would silently skip. **D90** records it.

### A0-4 — Prefixed imports are dynamic, and route by a closed prefix list

**Decided: the four prefixes of INTEROP §3 (`py`, `js`, `st`, `clj`) and no others.** A leading segment equal to one of them is stripped and the remainder goes to `getProviderForSpec("provider:<prefix>")->tryLoad(rest, ctx)`; everything else goes to the space's resolution chain. The tempting generalisation — "any registered provider alias is a prefix" — was rejected because it makes `import util.Strings` hijackable by a provider that happens to be aliased `util`, and a program's meaning must not depend on which plug-ins are installed. The four names are a closed, documented list in one header.

A foreign module binds a **`Val`**, not an `Object`: it has no `ClassInfo`, so its members resolve by name at run time (**D94**), and a wildcard import of one is refused because a foreign object's attribute names cannot be enumerated through the API this plan is allowed to use (**D92**). A *selector* import of a foreign member works, because the loader can read one named attribute at compile time.

**Prefixed imports do not go through `getImportModule`.** That is deliberate and it is a correctness point, not an optimisation: `getImportModule` consults protoCore's `SharedModuleCache`, which `core/ModuleCache.cpp` keys **by logical path with no `ProtoSpace` component** and never invalidates. In a two-runtime process (which Task 10 creates) a cached `numpy` could be handed to whichever runtime asked second. Calling `tryLoad` directly keeps each prefix bound to exactly the provider its name selects. The unprefixed path *does* use the chain and therefore the shared cache, which is R5's territory; Task 4 Step 6 records the hazard in STATUS under R5 rather than pretending it is not there.

### A0-5 — `ScalaModuleProvider`: alias, GUID, search order, exactly-once, cycles

**Decided**, following protoST's provider point for point:

- alias `scala`, GUID `protoScala-source-v1`; registered once per process with `std::call_once`, and the session registers itself in a `ProtoSpace`-keyed registry so `tryLoad` reaches it from any thread (a thread-local would answer "not found" on every actor worker — protoST's comment records that exact bug).
- `a.b.C` → `a/b/C.scala`, searched in this order: the **importing file's directory** first (INTEROP §2), then each colon-separated entry of `PROTOSCALA_PATH`, then the current working directory. A provider `tryLoad` called from *another runtime* has no importing file, so it starts at `PROTOSCALA_PATH`.
- "No file resolves" is a **miss**: `return PROTO_NONE`, never an error, because `ModuleResolver.cpp:99` needs a miss to move to the next chain entry.
- exactly-once per **canonical absolute path** (`std::filesystem::absolute`), with a loading set keyed by owner `std::thread::id`; a cycle raises `ImportError: cyclic module import: <logical path>`; a failed load is **not** cached, so a fixed file can be imported again in the same session (protoST's `LoadingEntryGuard`).
- the resolution chain is **prepended to**, not replaced: `provider:scala` is inserted at position 0 of whatever the space already has, so protoCore's default filesystem entries survive. protoPython prepends, protoST replaces; prepending is the one that does not silently delete another runtime's chain in a shared process.

### A0-6 — Import syntax accepted, and what each form binds

**Decided**, matching Scala 3 where it costs nothing:

| Form | Binds |
|---|---|
| `import util.Strings` | the name `Strings` → the module object (forced) |
| `import util.Strings as S` | the name `S` → the same |
| `import py.numpy as np` | the name `np` → the foreign module object |
| `import util.Strings.{trim, pad as p}` | compile-time aliases `trim` → `Strings.trim`, `p` → `Strings.pad` |
| `import util.Shapes.{Point}` | the **type** `Point` → the `ClassInfo` of `Shapes.Point`, and the term `Point` → its companion |
| `import util.Strings.*` | every exported member of the module as a compile-time alias, and every exported type as a type alias plus its companion |
| `import util.Strings._` | the same (Scala 2 spelling, accepted) |
| `import util.Strings.given` / `.{given T}` | parsed and **ignored** (D3: there are no givens) — **D93** |
| `import py.numpy.*` | **refused**: `a wildcard import of a foreign module is not supported: name the members you need` — **D92** |

**Module path versus member:** the loader tries the **longest** dotted prefix first and walks down. `import a.b.C` tries module `a.b.C`, then module `a.b` with member `C`, then module `a` with member `b.C`. The first that resolves wins; when none does, the error names **every** path tried:

```
ImportError: no module found for 'a.b.C' (tried a/b/C.scala, a/b.scala, a.scala on PROTOSCALA_PATH)
```

This is deterministic, it is what Scala's package-or-object resolution means, and the message makes a typo obvious in one read.

**An `import` is hoisted to its unit and is visible for the whole unit** (**D96**), where Scala scopes an import lexically. Lexical scoping needs a scope-aware name resolver the compiler does not have and D82's extensions already have the same shape, so the two are scoped together or not at all (A0-11).

### A0-7 — The boundary catch shape: the exact order, one template, an audited site list

**Decided: one template in `src/umd/ForeignBoundary.h`, applied at every site, in exactly the order ROADMAP prescribes**:

```cpp
try { /* the UMD or foreign call */ }
catch (FutureYield&)            { throw; }   // a cooperative suspension, not an error
catch (ScalaThrow&)             { throw; }   // a Scala exception already in flight
catch (ScalaError&)             { throw; }   // a native throw site's own translation
catch (const std::exception& e) { throw ScalaError("RuntimeException", e.what()); }
catch (...)                     { throw ScalaError("RuntimeException", "native exception"); }
```

The order is load-bearing and each clause earns its place. `FutureYield` is **not** a `std::exception` and must be first anyway, because a later `catch (...)` would eat it and a suspended actor would never resume. `ScalaThrow` derives from `std::exception` and **not** from `std::runtime_error`; without its clause the `std::exception` arm would rewrite every Scala exception crossing a module boundary into a `RuntimeException`, losing its class and its payload. `ScalaError` is already a translation and re-translating it would replace a precise class name with `RuntimeException`. `std::exception` carries `what()` through; `catch (...)` is the last resort and says so rather than inventing a message.

**The audited site list** (Task 7 visits every one and a test covers each): `ScalaModuleProvider::tryLoad`; `Session::load` and `Session::bindForeignMember` (the two `ModuleLoader` entry points, which call `tryLoad` and `getImportModule`); the provider plug-in entry point `protoScalaRegisterProviders`; and the foreign-send path — `ExecutionEngine::send`, `sendKeywords` and `callNative` already translate `std::` exceptions through the DESIGN §7 table, so they gain only the two missing pass-through clauses in the right position, not a second translation. `std::logic_error` is **still** not caught anywhere (D74): a VM or compiler defect must never be maskable by `catch { case e: Throwable => }`, and `catch (const std::exception&)` inside `translateForeignException` would catch it — so the template carries an explicit `catch (const std::logic_error&) { throw; }` **before** the `std::exception` arm, and a unit test pins it.

### A0-8 — Opcodes added in this phase: none

**Decided: zero.** The lowest free opcode is **40** and it stays free. An import resolves at compile time (A0-1) and binds a name to a global that already exists, so the import site emits **nothing at all**: `import util.Strings` produces no instruction, and a later use of `Strings` is the `PUSH_GLOBAL` + `FORCE` an `object` read already compiles to. A member alias compiles to the `SEND_APPLY` the qualified spelling compiles to. A foreign module's value is written into the globals object by the loader, so reading it is `PUSH_GLOBAL`. An `IMPORT_MODULE` opcode would add a run-time resolution step that the compile-time loader has already performed once, and a second way to reach a module. `docs/STATUS.md`'s opcode table is therefore unchanged by this phase, and Task 13 says so explicitly so a reader does not go looking.

### A0-9 — How the prelude's start-up cost is removed: a build-time image, invalidated by construction

**Decided: `protoscala-precompile` runs at build time and generates `PreludeImage.cpp`.** The measured cost is ~60 µs per prelude class across parse + desugar + compile + run (`benchmarks/RESULTS.md`, three interleaved rounds, monotone); the image removes parse, desugar and compile, and nothing removes run.

**Invalidation is not a run-time problem, because the image is not a cache.** It is a generated source file with an `add_custom_command` that `DEPENDS lib/prelude.scala`, so the build system regenerates it whenever the prelude changes — the same relationship `PreludeSource.cpp` already has with `lib/prelude.scala` through `configure_file`. There is no cache directory, no mtime comparison, no user-writable state and nothing to clear. Two belts are added anyway, because the failure mode of a stale image is a silently wrong prelude: the image carries `kImageFormatVersion` and `kPreludeSourceHash` (FNV-1a-64 of the prelude source), and `loadPrelude` compares them against the format version it was compiled with and against the hash of the **embedded source it ships beside**; a mismatch prints one line to stderr and falls back to compiling the source. The hash is 64-bit FNV-1a over ~10 KB, which is tens of microseconds, and Task 2 Step 7 measures it rather than assuming.

Cross-compilation is guarded: when `CMAKE_CROSSCOMPILING` is true the generator cannot run on the build host, so the image is not generated and `loadPrelude` takes the source path. The binary is then exactly what 0.5.0 ships.

### A0-10 — Which cold-start budget counts as met, and what happens if it is not — **ESCALATED (E5)**

**Decided for the measurable part:** the budget is DESIGN §1's `< 25 ms`, verified by `benchmarks/cold-start.sh build_release/protoscala 21` exiting 0 with `verified=21` on both the script and the REPL case, on a host whose load average is recorded next to the figure. It is a **done-when**, not an aspiration: Task 2 is not done until that command exits 0.

**Escalated:** if Task 1's attribution shows the **run** phase dominates — that is, if removing parse + desugar + compile leaves the median at or above 25 ms — then the remaining cost is executing `MAKE_CLASS`/`MAKE_FN`/`STORE_GLOBAL` for the prelude's ~40 classes, and protoScala cannot remove it. protoCore has **no object-graph serialisation, no image and no snapshot API** (verified across `headers/protoCore.h` and `proto_internal.h`; the only caching facility is the in-process `SharedModuleCache`, which holds live objects and cannot cross a process). Meeting the budget would then need either a protoCore space image — a new protoCore capability, P3, maintainer-owned — or a change to DESIGN §1's number, which is a published promise in the README. **Both are maintainer calls, and the plan brings the measurement rather than a guess.**

### A0-11 — Import scoping for extension methods (D82) — **ESCALATED (E6)**

D82 records that an extension is global and session-wide, with the note "Scoping needs an import mechanism, which arrives with UMD in Phase 6". The mechanism now arrives, so the question is live: **should an extension become visible only where it is imported?**

This is escalated and not decided here on the line the maintainer drew. It is a **public-surface change**: scoping an extension changes what an existing program means (an extension defined in a module and used without importing it stops working), it is how Scala 3 code organises extensions, and it interacts with **D96** — protoScala hoists an import to its unit, so "scoped" would mean per-*unit*, not per-*block*, which is a third behaviour that is neither Scala's nor today's. Task 9 is written for both rulings and does nothing until one arrives; A0-12 says what the default is if it does not.

### A0-12 — Converting `foreign-python-keyword.scala` and `foreign-python-open-encoding.scala` — **ESCALATED (E7)**

ROADMAP's Phase 4 hand-off asks this phase to convert the two `XFAIL` fixtures to `EXPECT`, on the grounds that "what is missing is only `import py.…` routing". **The routing is not what is missing, and this plan cannot convert them honestly.** Three facts, each verified:

1. **No runtime in the family registers the alias `py`.** protoPython registers `native` (GUID `protoPython.native`), `python_stdlib`, `compiled` and `hpy`. `getProviderForSpec("provider:py")` returns `nullptr` today and would keep returning `nullptr` after this phase. INTEROP §3 already says this in its own words: *"Aliases `py`, `js`, `clj` therefore need work in those runtimes; this is coordinated, not assumed."*
2. **protoPython's providers are registered by `PythonEnvironment`'s initialisation**, so having them in the `protoscala` process means constructing a whole second runtime in that process — which is exactly **R5**, "one runtime per process (process-global UMD module cache)", a maintainer-owned risk.
3. `protoscala` links protoCore and libreadline and nothing else; there is no mechanism by which numpy could be reached.

So ROADMAP's hand-off contradicts ROADMAP's own done-when (which asks only for "a stand-in provider, and protoST's provider when both are built"), INTEROP §3, and DESIGN §11's R5. **A contradiction between documents is escalation territory.** The recommendation the maintainer is asked to rule on is in E7; **the default this plan implements if no ruling arrives** is: keep both fixtures `XFAIL`, **rewrite their directive line** so it names the real blocker instead of the wrong one, and prove the mechanism end to end against a provider protoScala can honestly load — the stand-in plug-in of Task 6 and, when protoST is built, protoST's own `st` provider (Task 10).

**What must not happen, and Task 8 says so in the fixture:** the two fixtures must **not** be converted by registering a stand-in under the alias `py` and having it answer `float64`. That would be a green test asserting numpy behaviour against a stub — a fixture that looks like success and is a crash, which is the exact failure mode the family's benchmark harness learned to reject. A fake provider is legitimate only when the fixture is named for what it is.

### A0-13 — The provider plug-in mechanism

**Decided: `dlopen`, discovered from `PROTOSCALA_PROVIDERS` and from `<prefix>/lib/protoscala/providers/`.** A plug-in is a shared object exporting two `extern "C"` symbols; `Session` loads them after the prelude and before the first user unit compiles. The precedent is protoPython's `CompiledModuleProvider`, which `dlopen`s with `RTLD_NOW | RTLD_GLOBAL` and `dlsym`s a fixed init symbol.

The alternative — statically linking every sibling runtime into `protoscala` — was rejected on three counts: it multiplies the binary and the start-up work this phase exists to reduce; it makes every runtime co-resident by construction, which is R5's hazard rather than a decision; and it makes protoScala's build depend on five sibling repositories.

**protoScala ships no plug-in of its own** except the test double of Task 6, which is built only by the test target. The mechanism is real and installed; whether a sibling runtime may be co-resident stays an R5 question for the maintainer, and Task 10 is the experiment that produces evidence for it.

### A0-14 — `ImportError`

**Decided: one new prelude class, `class ImportError(message: String) extends RuntimeException(message)`.** Scala has no `ImportError`, so nothing is being diverged from; a failed import must be a catchable `Throwable` with a name that says what failed, and `RuntimeException` is the base every native translation already falls back to. The cost is one prelude class — about 60 µs of start-up at 0.5.0's rate, which Task 2's image removes. It is the only prelude class this phase adds.

### A0-15 — Which existing deviations this phase touches

- **D82** (extensions are global) — retired or restated by Task 9, depending on E6.
- **D96** is the import-shaped twin of D82 and is recorded whichever way E6 goes, because hoisting an import to its unit is this phase's own choice.
- Nothing else retires. **D3** (no givens) is why `given` selectors are ignored; **D4** (types erased) is why an imported type contributes membership markers and not a type check; **D10** (`SEND_APPLY`) is what makes a module member callable whether it is a method or a function value; **D25**'s shadowing keys are what make a module's globals collision-free in one session (A0-16).

### A0-16 — Where a module's globals live, and why they cannot collide

A module is compiled with a `GlobalTable` **copied from the session's post-prelude snapshot**. The copy matters twice: the module sees the prelude (it needs `List`, `Option`, `println`) and nothing of the importer, and the copy **shares the key counters** (`GlobalTable::counters_` is a `shared_ptr` carried by every copy), so the module's `trim` gets the key `trim` or `trim#1` and can never collide with a session global of the same name. The same holds for type keys. Its values live in the one session-wide globals object, which is pinned in a root-context slot (P1). No new rooting mechanism is introduced, and the module table's `ProtoObject*` is an index over something already rooted.

## Design notes that apply to several tasks

File:line references are to the trees of 2026-09-24 (`01fea56`).

1. **`Session::evaluate` compiles against a trial table.** `src/repl/Session.cpp:78` does `GlobalTable trial = globals_;` and commits only on success, so a failed REPL line defines nothing. A module loaded while compiling that line has **already run** and stays loaded — its values are in the globals object under keys that are never reused, so the leftover is unreachable and harmless. Task 3 Step 8 states this in a comment at the commit point rather than leaving a reader to wonder.

2. **The compiler's context problem, and its answer.** `Compiler` is pure C++ and must stay so (DESIGN §3.3); `tryLoad` and `getImportModule` need a `ProtoContext*`. The `ModuleLoader` interface is the seam: the compiler passes strings and gets back PODs, and the loader — `Session` — creates a child context of the root context for the load and destroys it when the load returns (P2).

3. **`ProtoSpace`-keyed registry, not thread-local.** `tryLoad` receives only `logicalPath` and `ctx`, so it finds its session through `ctx->space`. protoST's header records the bug a thread-local caused: `Import from:` answered "module not found" on every thread but the constructing one. The containers are **intentionally leaked** because a session can be destroyed during static destruction, after a function-local static container would be gone.

4. **A miss is `PROTO_NONE`, an error is an exception.** `core/ModuleResolver.cpp:99` treats `nullptr` and `PROTO_NONE` alike as "try the next chain entry". A provider that raises for "not mine" breaks the chain for every other provider. A provider that returns `PROTO_NONE` for a genuine failure hides it. Task 4 Step 4's two fixtures pin both halves.

5. **`getImportModule` returns a wrapper.** The module is under the attribute named by `attrName2create`. Unwrap it with a symbol read out of `RuntimeLayout` (`exportsKey`), never a function-local static — protoST's `prim_Import_from` carries the comment saying why.

6. **Phase 4's nested-template machinery is the module machinery.** `Desugar` lifts a template nested in an `object` to a qualified name (`O.C`), keeps the qualified name for resolution and shows the simple one, qualifies a sibling named in an `extends` clause at lift time, and resolves an unqualified sibling in expressions, types and extractor patterns by trying the enclosing prefixes innermost-first. A module is an `object`, so all of it applies unchanged; Task 3 adds **no** lifting code.

7. **`SEND_APPLY` (opcode 79) is why a module member needs no special case.** It "calls the member when it is a method, else applies its value" (D10), so `Strings.trim("x")` works whether `trim` compiled to a method on the object's prototype or to a function value in an attribute.

8. **A module object must be mutable.** `newChild(ctx, true)`, as protoST's `loadModuleFromFile` does: an immutable object's `setAttribute` answers a **new** object, so the exports written after the first one would land on a different object than the one already handed out.

9. **The module table's mutex and the GC.** A thread waiting for another thread's in-progress load waits inside `proto::ProtoContext::UnmanagedScope`, so the collector does not wait for it (P6). The mutex is held only for the container operation, never across a compile or a run.

10. **`BytecodeModule` ownership is why the image is tables, not a blob.** A module and its blocks are `std::unique_ptr`s owned by the session, and a function object points at its module through a `SmallInteger` holding the **address** (`MAKE_FN`). The image therefore has to produce real `BytecodeModule` objects, which is what `buildPreludeImage` does — it is a constructor driven by static data, not a `memcpy` of a serialised graph, and no address is ever baked into the generated file.

11. **`linkSymbols` is the boundary the image stops at.** The generated tables hold **strings**, never `ProtoObject*`; `buildPreludeImage` produces unlinked modules and `loadPrelude` calls `linkSymbols(ctx)` exactly as it does today. That is what keeps the image space-independent and P1-clean, and it is also a cost the image does not remove — Task 1 measures `linkSymbols` as its own stage for that reason.

12. **`ClassInfo` is the bulkiest thing the image carries** — name, key, six flags, a linearization, fields, constructor parameters, arities, by-name masks, a member map and four companion fields. It is plain C++ and needs no interning, so the generator can emit it as an initialiser list. Its *size* is the reason Task 2 Step 3 emits it as a table walked by a loop rather than as one enormous literal.

13. **Rooting across an allocation.** Anything built in a loop inside the loader must live in a slot or in an already-rooted structure, not a C++ local, across an allocation — the Phase 5 `Mailbox::push` bug. In this phase that applies to writing a module's exports onto the module object one attribute at a time: the module object goes into the globals object **first**, then the attributes are written.

14. **The cold-start script is the only benchmark that matters here and it already self-reports.** `benchmarks/cold-start.sh` counts `verified=` runs and fails the case when any run printed the wrong last line, before it compares the median with `TARGET_MS=25`. It is deliberately **not** a CTest case (timing depends on the host), and Phase 6 does not add it to one.

15. **Two fixtures need a module tree on disk.** They live under `tests/conformance/24-modules/_modules/` (a `_`-prefixed directory, so the runner does not treat its files as fixtures) and the CTest case sets `PROTOSCALA_PATH` through `set_tests_properties(... PROPERTIES ENVIRONMENT ...)`, as the Phase 5 block already does for `PROTOSCALA_ACTOR_WORKERS`.

```cpp
protoScala::PreludeTiming g_timing;
using Clock = std::chrono::steady_clock;
double usSince(Clock::time_point t0) {
    return std::chrono::duration<double, std::micro>(Clock::now() - t0).count();
}
}  // namespace

namespace protoScala {

const PreludeTiming& preludeTiming() { return g_timing; }

void loadPrelude(proto::ProtoContext* parent, ExecutionEngine& engine, GlobalTable& globals,
                 std::vector<std::unique_ptr<BytecodeModule>>& modules) {
    auto where = [](SourcePos p) {
        return " (lib/prelude.scala:" + std::to_string(p.line) + ":" + std::to_string(p.column) + ")";
    };
    const auto tStart = Clock::now();
    try {
        auto t0 = Clock::now();
        auto unit = parseSource(preludeSource());
        g_timing.parseUs = usSince(t0);

        t0 = Clock::now();
        desugar(*unit);
        g_timing.desugarUs = usSince(t0);

        t0 = Clock::now();
        Compiler compiler(globals);
        CompiledUnit cu = compiler.compileUnit(*unit, UnitMode::Script, 0);
        g_timing.compileUs = usSince(t0);

        t0 = Clock::now();
        cu.module->linkSymbols(parent);
        g_timing.linkUs = usSince(t0);

        const BytecodeModule& mod = *cu.module;
        modules.push_back(std::move(cu.module));

        t0 = Clock::now();
        engine.run(parent, mod);
        g_timing.runUs = usSince(t0);
    } catch (const ParseError& e) {
        throw std::logic_error(std::string("prelude: ") + e.what() + where(e.pos));
    } catch (const CompileError& e) {
        throw std::logic_error(std::string("prelude: ") + e.what() + where(e.pos));
    } catch (const ScalaError& e) {
        throw std::logic_error(std::string("prelude: ") + e.what());
    }
    g_timing.totalUs = usSince(tStart);
    if (const char* v = std::getenv("PROTOSCALA_PRELUDE_TIMING"); v && *v)
        std::fprintf(stderr,
                     "prelude: parse=%.0fus desugar=%.0fus compile=%.0fus link=%.0fus "
                     "run=%.0fus total=%.0fus image=%d\n",
                     g_timing.parseUs, g_timing.desugarUs, g_timing.compileUs, g_timing.linkUs,
                     g_timing.runUs, g_timing.totalUs, g_timing.fromImage ? 1 : 0);
}
```

```cpp
/*
 * PreludeImage — the compiled prelude as a BUILD PRODUCT, not a cache.
 *
 * `PreludeImage.cpp` is generated at build time by `protoscala-precompile`
 * from lib/prelude.scala, through an add_custom_command that DEPENDS on that
 * file. There is no cache directory, no mtime comparison and nothing a user
 * can invalidate: the image is regenerated whenever the source changes, in the
 * same way PreludeSource.cpp already is.
 *
 * Two guards catch a hand-copied or hand-edited image, because a stale prelude
 * would be silently wrong rather than loudly broken:
 *   - kImageFormatVersion must equal the version this binary was compiled with;
 *   - kPreludeSourceHash must equal preludeSourceHash(), the FNV-1a-64 of the
 *     prelude source embedded in the same binary.
 * On either mismatch loadPrelude prints one line to stderr and compiles the
 * embedded source instead, so the binary is always correct and only slower.
 *
 * The image holds no ProtoObject* and no address: it holds strings, integers
 * and PODs, and buildPreludeImage CONSTRUCTS BytecodeModule objects from them.
 * linkSymbols still runs afterwards, exactly as on the source path (design
 * note 11), which is what keeps the image independent of any ProtoSpace.
 */
#pragma once
#include "compiler/BytecodeModule.h"
#include "compiler/GlobalTable.h"

#include <cstdint>
#include <memory>
#include <vector>

namespace protoScala {

// Bumped by hand whenever the generated tables change shape. A binary refuses
// an image that does not match, and falls back to the source.
inline constexpr std::uint32_t kPreludeImageFormat = 1;

// Present only when an image was generated (absent when cross-compiling).
#if defined(PROTOSCALA_HAVE_PRELUDE_IMAGE)
std::uint32_t preludeImageFormat();
std::uint64_t preludeImageSourceHash();

// to `modules` and fills `globals` with exactly the bindings and ClassInfos the
// compiler produced. The returned module is NOT linked; the caller calls
// linkSymbols on it.
const BytecodeModule& buildPreludeImage(GlobalTable& globals,
                                        std::vector<std::unique_ptr<BytecodeModule>>& modules);
#endif

// FNV-1a-64 of the prelude source embedded in this binary. Computed once,
// lazily, over ~10 KB.
std::uint64_t preludeSourceHash();

} // namespace protoScala
```

```cpp
namespace protoScala {

const char* preludeSource() {
    return R"proto_prelude(@PROTOSCALA_PRELUDE_SOURCE@)proto_prelude";
}

// FNV-1a-64 over the embedded source. Computed once: the image check needs it
// on every start-up, and hashing ~10 KB is tens of microseconds, which Step 7
// measures rather than assumes.
std::uint64_t preludeSourceHash() {
    static const std::uint64_t h = [] {
        std::uint64_t acc = 0xcbf29ce484222325ull;
        for (const char* p = preludeSource(); *p; ++p) {
            acc ^= static_cast<std::uint64_t>(static_cast<unsigned char>(*p));
            acc *= 0x100000001b3ull;
        }
        return acc;
    }();
    return h;
}

} // namespace protoScala
```

```cpp
/*
 * protoscala-precompile — a BUILD-TIME host tool. It reads lib/prelude.scala,
 * runs the same lexer, parser, desugarer and compiler the runtime would, and
 * writes PreludeImage.cpp: static tables plus buildPreludeImage(), which
 * reconstructs the BytecodeModule tree and the GlobalTable without a lexer,
 * a parser, a desugarer or a compiler in the path.
 *
 * It links protoscala_compiler and protoscala_support only. It never creates a
 * ProtoSpace and never calls linkSymbols: the image is space-independent.
 *
 * Usage: protoscala-precompile <prelude.scala> <out.cpp>
 */
#include "compiler/Compiler.h"
#include "frontend/Desugar.h"
#include "frontend/Parser.h"
#include "support/PreludeImage.h"

#include <cstdio>
#include <fstream>
#include <iostream>
#include <sstream>

using namespace protoScala;

int main(int argc, char** argv) {
    if (argc != 3) {
        std::fprintf(stderr, "usage: protoscala-precompile <prelude.scala> <out.cpp>\n");
        return 2;
    }
    std::ifstream in(argv[1], std::ios::binary);
    if (!in) { std::fprintf(stderr, "protoscala-precompile: cannot read %s\n", argv[1]); return 1; }
    std::ostringstream buf;
    buf << in.rdbuf();
    const std::string source = buf.str();

    GlobalTable globals;
    for (const auto& n : builtinGlobalNames()) globals.declare(n, BindingKind::Builtin);
    for (ClassInfo& t : builtinTypes()) globals.defineBuiltinType(std::move(t));

    std::unique_ptr<CompilationUnit> unit;
    CompiledUnit cu;
    try {
        unit = parseSource(source);
        desugar(*unit);
        Compiler compiler(globals);
        cu = compiler.compileUnit(*unit, UnitMode::Script, 0);
    } catch (const ParseError& e) {
        std::fprintf(stderr, "%s:%d:%d: error: %s\n", argv[1], e.pos.line, e.pos.column, e.what());
        return 1;
    } catch (const CompileError& e) {
        std::fprintf(stderr, "%s:%d:%d: error: %s\n", argv[1], e.pos.line, e.pos.column, e.what());
        return 1;
    }
    return emitImage(argv[2], source, globals, *cu.module) ? 0 : 1;
}
```

`builtinGlobalNames()` is a problem to solve rather than to paper over: it lives in `src/runtime/Primitives.h`, which the tool must not link. - [ ] **Step 3: Write the generator's back half — emit the tables**

Still in `src/tools/PrecompileMain.cpp`, `emitImage` walks the module tree and writes one `.cpp`. Emit **tables walked by a loop**, never one giant literal (design note 12). The shape, for the code and constants of every module in the tree flattened into `kModules`:

```cpp
static void emitString(std::ostream& o, const std::string& s) {
    o << '"';
    for (unsigned char c : s) {
        if (c == '"' || c == '\\') o << '\\' << static_cast<char>(c);
        else if (c == '\n') o << "\\n";
        else if (c >= 0x20 && c < 0x7f) o << static_cast<char>(c);
        else { char b[8]; std::snprintf(b, sizeof b, "\\x%02x", c); o << b; }
    }
    o << '"';
}

```

The module tree is flattened depth-first into one array, each record naming the index of its enclosing module (`-1` for the top level), so the blocks can be reattached in index order and every block index baked into a `MAKE_FN` operand stays exactly what the compiler emitted. The record layout is `ModuleRec`, below.

The generated file has this structure, and the `buildPreludeImage` half is **fixed code that the generator copies verbatim** — it is not generated logic, so it cannot drift per prelude:

```cpp
// Generated by protoscala-precompile from lib/prelude.scala; do not edit.
#include "support/PreludeImage.h"

namespace protoScala {
namespace {

struct ConstRec { std::uint8_t kind; long long ival; double dval; const char* sval;
                  int base; std::uint32_t argc; std::uint32_t flags; bool exact;
                  int namesFirst, namesCount, fieldsFirst, fieldsCount; const char* key; };
struct HandlerRec { std::uint32_t start, end, body; int stackDepth, slot; std::uint8_t kind; };
struct CaptureRec { int parentSlot, localSlot; };
struct ModuleRec { int parent; const char* name; int arity; bool variadic; int localCount;
                   int maxStack; bool method; bool paramless;
                   int codeFirst, codeCount, constFirst, constCount,
                       handlerFirst, handlerCount, captureFirst, captureCount,
                       paramFirst, paramCount, defaultFirst, defaultCount; };

constexpr std::uint32_t kCode[] = { /* ... */ };
constexpr int kLines[] = { /* ... */ };
const char* const kStrings[] = { /* ... */ };       // every name, in one pool
constexpr ConstRec kConsts[] = { /* ... */ };
constexpr HandlerRec kHandlers[] = { /* ... */ };
constexpr CaptureRec kCaptures[] = { /* ... */ };
constexpr ModuleRec kModules[] = { /* ... */ };
// GlobalTable: one record per binding and one per type.
struct BindingRec { const char* name; std::uint8_t kind; const char* key;
                    int maskFirst, maskCount; };
struct TypeRec { const char* name; const char* key; std::uint8_t kind; std::uint32_t flags;
                 int linFirst, linCount, fieldFirst, fieldCount, ctorFirst, ctorCount,
                     memberFirst, memberCount; std::size_t primaryArity, primaryMinArity;
                 const char* companionTermKey; const char* companionTypeKey; };
constexpr BindingRec kBindings[] = { /* ... */ };
constexpr TypeRec kTypes[] = { /* ... */ };

}  // namespace

std::uint32_t preludeImageFormat() { return 1u; }
std::uint64_t preludeImageSourceHash() { return 0x0123456789abcdefull; }  // of lib/prelude.scala

const BytecodeModule& buildPreludeImage(GlobalTable& globals,
                                        std::vector<std::unique_ptr<BytecodeModule>>& modules) {
    // Fixed reconstruction. It is copied verbatim into every generated file, so
    // it cannot drift per prelude; only the tables above change.
    const std::size_t n = std::size(kModules);
    std::vector<std::unique_ptr<BytecodeModule>> built(n);
    // Bottom-up, so a parent can addBlock its children in index order and the
    // block indices baked into MAKE_FN's operands stay exactly what the
    // compiler emitted.
    for (std::size_t i = n; i-- > 0;) {
        const ModuleRec& r = kModules[i];
        auto m = std::make_unique<BytecodeModule>();
        m->setName(r.name);
        m->setArity(r.arity);
        m->setVariadic(r.variadic);
        m->setLocalCount(r.localCount);
        m->setMaxStack(r.maxStack);
        m->setMethod(r.method);
        m->setParamless(r.paramless);
        // Replay the pool through the add* methods, in the compiler's original
        // order, so the de-duplication produces identical indices. Assigning
        // slots directly would run and be wrong.
        for (int k = 0; k < r.constCount; ++k) replayConst(*m, kConsts[r.constFirst + k]);
        for (int k = 0; k < r.codeCount; ++k)
            m->appendRawInstr(kCode[r.codeFirst + k], kLines[r.codeFirst + k]);
        for (int k = 0; k < r.handlerCount; ++k) {
            const HandlerRec& h = kHandlers[r.handlerFirst + k];
            m->addHandler(BytecodeModule::Handler{h.start, h.end, h.body, h.stackDepth, h.slot,
                                                  static_cast<BytecodeModule::HandlerKind>(h.kind)});
        }
        for (int k = 0; k < r.captureCount; ++k)
            m->addCapture(kCaptures[r.captureFirst + k].parentSlot,
                          kCaptures[r.captureFirst + k].localSlot);
        replayParams(*m, r);   // setParamNames + setDefaultBlock, in declaration order
        built[i] = std::move(m);
    }
    for (std::size_t i = n; i-- > 0;)
        if (kModules[i].parent >= 0)
            built[static_cast<std::size_t>(kModules[i].parent)]->addBlock(std::move(built[i]));
    for (const BindingRec& b : kBindings)
        globals.bind(b.name, GlobalBinding{static_cast<BindingKind>(b.kind), b.key,
                                           masksOf(b.maskFirst, b.maskCount)});
    for (const TypeRec& t : kTypes) {
        globals.aliasType(t.name, t.key);
        globals.defineType(classInfoOf(t));
    }
    modules.push_back(std::move(built[0]));
    return *modules.back();
}

} // namespace protoScala
```

The table initialisers are **generator output**: `emitImage` writes them, an implementer never types them. `replayConst`, `replayParams`, `masksOf` and `classInfoOf` are four small helpers in the same fixed block, one per record type. `appendRawInstr(word, line)` is the one addition `BytecodeModule` needs — `emit(op, operand, line)` re-encodes and would refuse an `EXTEND`-prefixed word the compiler already assembled, so the image appends the assembled words and their line entries directly; declare it next to `emit` with a comment saying it exists for the image and for nothing else.

Two invariants the generator must respect, both of which are silent if broken and so each gets a test in Step 6: **constant-pool indices must come out identical**, which is why the reconstruction replays `addInt`/`addString`/`addSendSite`/… in the compiler's original order rather than assigning slots directly; and **block indices must come out identical**, because `MAKE_FN`'s operand is a block index baked into `kCode`.

```cpp
// `import` (Phase 6): a dotted path, then optionally `as <alias>` or a brace
// selector list. `text` is still the original spelling, for messages.
NodePtr Parser::parseImport() {
    auto node = std::make_unique<Import>(expect(TokenKind::KwImport, "'import'").pos);
    for (;;) {
        const Token& t = peek();
        if (t.kind == TokenKind::Identifier || t.kind == TokenKind::KwThis) {
            node->path.push_back(t.text);
            node->text += t.backquoted ? "`" + t.text + "`" : t.text;
            advance();
        } else {
            fail("import selector expected", t);
        }
        if (peek().kind != TokenKind::Dot) break;
        node->text += ".";
        advance();
        // `a.b.*`, `a.b._` and `a.b.{...}` end the path and open the selectors.
        if (peek().kind == TokenKind::LBrace) { parseImportSelectors(*node); return node; }
        if (isWildcardToken(peek())) {
            ImportSelector s; s.wildcard = true; s.name = "*"; s.pos = peek().pos;
            node->text += spelling(peek());
            advance();
            node->selectors.push_back(std::move(s));
            return node;
        }
    }
    if (peek().kind == TokenKind::Identifier && !peek().backquoted && peek().text == "as") {
        advance();
        const Token& a = expect(TokenKind::Identifier, "an alias after 'as'");
        node->moduleAlias = a.text;
        node->text += " as " + a.text;
    }
    if (node->path.empty()) fail("import selector expected", peek());
    return node;
}
```

`parseImportSelectors` handles `{a, b as c, given T, *}`, filling one `ImportSelector` each and reproducing the existing `text` spacing rules (`, ` after a comma, blanks around `as` and `=>`) so the message in `test_parser.cpp` does not change. `isWildcardToken` accepts `*` and `_`.

```cpp
void desugarModule(CompilationUnit& unit, const std::string& objectName) {
    // A module file is a library: an @main in it would never be called, and a
    // silently ignored one is a trap (D91).
    for (const NodePtr& s : unit.statements) {
        if (s->kind == NodeKind::DefDef && static_cast<const DefDef&>(*s).isMain)
            throw ParseError("a module may not define an @main method: " + objectName +
                             " is imported, not run", s->pos);
    }
    auto obj = std::make_unique<TemplateDef>(unit.statements.empty() ? SourcePos{}
                                                                    : unit.statements.front()->pos);
    obj->kind = TemplateKind::Object;
    obj->name = objectName;
    obj->synthetic = true;
    obj->body = std::move(unit.statements);
    unit.statements.clear();
    unit.statements.push_back(std::move(obj));
    // From here it is an ordinary unit with one `object` in it, so Phase 4's
    // lifting, companion synthesis and sibling qualification all apply
    // unchanged (design note 6).
    desugar(unit);
}
```

```cpp
/*
 * ScalaModuleProvider — protoScala as a protoCore UMD provider (DESIGN §9,
 * INTEROP §2). Alias "scala", GUID "protoScala-source-v1".
 *
 * It is stateless. tryLoad receives only a logicalPath and a ProtoContext, so
 * it finds the session that owns ctx->space through a ProtoSpace-keyed
 * registry — protoST's STModuleProvider pattern, adopted rather than invented.
 * A thread-local would answer "not found" on every actor worker, which is the
 * bug protoST's header records.

#pragma once
#include "protoCore.h"

#include <memory>
#include <string>

namespace protoScala {

struct LoadedModule;

// What the provider needs from the session that owns the space.
class ModuleHost {
public:
    virtual ~ModuleHost() = default;
    // "a.b.C" -> the canonical absolute path of a/b/C.scala, or "" for a MISS.
    // `importerDir` is "" when the call came from protoCore's resolver.
    virtual std::string findModuleFile(const std::string& logicalPath,
                                       const std::string& importerDir) = 0;
    // The paths findModuleFile tried, joined with ", ", for the error message.
    virtual std::string triedPathsOf(const std::string& logicalPath,
                                     const std::string& importerDir) = 0;
    // Parses, desugars, compiles and RUNS the file exactly once per canonical
    // path, and returns the entry. Throws std::runtime_error on a cycle or a
    // failure inside the module.
    virtual const LoadedModule& loadModuleFile(proto::ProtoContext* ctx,
                                               const std::string& absPath,
                                               const std::string& logicalPath) = 0;
};

class ScalaModuleProvider : public proto::ModuleProvider {
public:
    ScalaModuleProvider() : guid_("protoScala-source-v1"), alias_("scala") {}
    const proto::ProtoObject* tryLoad(const std::string& logicalPath,
                                      proto::ProtoContext* ctx) override;
    const std::string& getGUID() const override { return guid_; }
    const std::string& getAlias() const override { return alias_; }

private:
    std::string guid_;
    std::string alias_;
};

// thread that can import is started and unregisters after those threads are
// joined. The containers are intentionally leaked: a Session can be destroyed
// during static destruction, after a function-local static would be gone.
void registerModuleHost(const proto::ProtoSpace* space, ModuleHost* host);
```

- [ ] **Step 1: The space-keyed host registry**

`src/umd/ScalaModuleProvider.cpp`, copying protoST's shape:

```cpp
namespace {
struct HostEntry { const proto::ProtoSpace* space; protoScala::ModuleHost* host; };
// Intentionally leaked: a Session may be destroyed during static destruction,
// after a function-local static container would already be gone (protoST's
// STModuleProvider.cpp carries the same comment for the same reason).
std::vector<HostEntry>* g_hosts = new std::vector<HostEntry>();
std::mutex* g_hostsMu = new std::mutex();
}  // namespace

void registerModuleHost(const proto::ProtoSpace* space, ModuleHost* host) {
    std::lock_guard<std::mutex> lock(*g_hostsMu);
    for (HostEntry& e : *g_hosts)
        if (e.space == space) { e.host = host; return; }
    g_hosts->push_back(HostEntry{space, host});
}

void unregisterModuleHost(const proto::ProtoSpace* space, ModuleHost* host) {
    std::lock_guard<std::mutex> lock(*g_hostsMu);
    g_hosts->erase(std::remove_if(g_hosts->begin(), g_hosts->end(),
                                  [&](const HostEntry& e) {
                                      return e.space == space && e.host == host;
                                  }),
                   g_hosts->end());
}

ModuleHost* moduleHostForSpace(const proto::ProtoSpace* space) {
    std::lock_guard<std::mutex> lock(*g_hostsMu);
    for (const HostEntry& e : *g_hosts)
        if (e.space == space) return e.host;
    return nullptr;
}
```

```cpp
    // std::call_once around registerProvider). ProviderRegistry::instance() is
```

`loadModuleFile` is the exactly-once loader, over `ModuleTable`:

```cpp
const LoadedModule& Session::loadModuleFile(proto::ProtoContext* ctx, const std::string& absPath,
                                            const std::string& logicalPath) {
    if (const LoadedModule* hit = modules_by_path_.find(absPath)) return *hit;
    if (!modules_by_path_.claim(absPath, logicalPath)) {
        // Another thread is loading it. Park OUTSIDE the collector's view so a
        // waiting importer never holds up a collection (P6).
        proto::ProtoContext::UnmanagedScope unmanaged(ctx);
        if (const LoadedModule* m = modules_by_path_.awaitLoaded(absPath)) return *m;
        throw std::runtime_error("module failed to load: " + logicalPath);
    }
    // A failed load is NOT published, so a fixed file can be imported again.
    struct Guard {
        ModuleTable& t; const std::string& p; bool done = false;
        ~Guard() { if (!done) t.abandon(p); }
    } guard{modules_by_path_, absPath};

    const std::string source = readFile(absPath);
    auto unit = parseSource(source);
    desugarModule(*unit, moduleObjectName(logicalPath));   // the last dotted segment
    GlobalTable table = preludeGlobals_;                   // shares the key counters (A0-16)
    table.beginUnit();
    Compiler compiler(table);
    compiler.setModuleLoader(this);
    compiler.setSourceDir(std::filesystem::path(absPath).parent_path().string());
    CompiledUnit cu = compiler.compileUnit(*unit, UnitMode::Script, 0);
    cu.module->linkSymbols(ctx);
    const BytecodeModule& mod = *cu.module;
    modules_.push_back(std::move(cu.module));              // the session keeps every module alive
    engine_.run(ctx, mod);

    LoadedModule m;
    m.exports = collectExports(ctx, table, moduleObjectName(logicalPath));
    // Root it through the ONE pinned structure before it enters the map (P1):
    // the module object is the value of its own session global, and the globals
    // object is pinned in a root-context slot.
    m.object = readGlobal(ctx, m.exports.moduleKey);
    modules_by_path_.publish(absPath, std::move(m));
    guard.done = true;
    return *modules_by_path_.find(absPath);
}
```

```cpp
const ModuleExports& Session::loadForeign(const std::string& providerSpec,
                                          const std::string& logicalPath, SourcePos pos) {
    const std::string cacheKey = providerSpec + "/" + logicalPath;
    if (auto it = foreignModules_.find(cacheKey); it != foreignModules_.end()) return it->second;

    proto::ModuleProvider* provider = proto::ProviderRegistry::instance().getProviderForSpec(providerSpec);
    if (!provider) {
        const std::string alias = providerSpec.substr(std::string("provider:").size());
        throw CompileError("ImportError: no provider registered for '" + alias +
                           "'. Install the runtime that provides it, or point "
                           "PROTOSCALA_PROVIDERS at its plug-in", pos);
    }
    proto::ProtoContext ctx(&space_, runtime_.rootContext());
    const proto::ProtoObject* mod = nullptr;
    try {
        mod = translateForeignException([&] { return provider->tryLoad(logicalPath, &ctx); });
    } catch (const ScalaError& e) {
        throw CompileError(std::string("ImportError: ") + e.what(), pos);
    }
    if (!mod || mod == PROTO_NONE)
        throw CompileError("ImportError: provider '" + providerSpec + "' has no module '" +
                           logicalPath + "'", pos);

    ModuleExports ex;
    ex.foreign = true;
    ex.moduleKind = BindingKind::Val;
    ex.moduleName = lastSegmentOf(logicalPath);
    ex.moduleKey = "__module" + std::to_string(++moduleCounter_) + "$" + ex.moduleName;
    // The value goes into the pinned globals object; nothing else holds it (P1).
    runtime_.layout().globals->setAttribute(
        &ctx, proto::ProtoString::createSymbol(&ctx, ex.moduleKey.c_str()), mod);
    return foreignModules_.emplace(cacheKey, std::move(ex)).first->second;
}
```

The key's `$` is what keeps it out of every Scala namespace: `$` cannot occur in a protoScala identifier, exactly as `@` and `#` already cannot.

```cpp
/*
 * Provider plug-ins (plan A0-13). A plug-in is a shared object that registers
 * one or more protoCore ModuleProviders. protoScala ships none: the mechanism
 * exists so a sibling runtime CAN be present, and whether two runtimes may be
 * co-resident in one process stays R5's question for the maintainer.
 *
 * The ABI a plug-in must export:
 *
 *   extern "C" const char* protoScalaProviderABI(void);
 *       // returns kProviderPluginABI exactly; anything else is refused
 *   extern "C" int protoScalaRegisterProviders(proto::ProtoSpace* space);
 *       // registers with proto::ProviderRegistry::instance(); 0 on success
 *
 * Discovery order: each colon-separated entry of PROTOSCALA_PROVIDERS (a .so
 * file, or a directory whose *.so files are loaded in sorted order), then
 * <prefix>/lib/protoscala/providers/. dlopen uses RTLD_NOW | RTLD_GLOBAL, as
 * protoPython's CompiledModuleProvider does, so a plug-in's own dependencies
 * resolve. Handles are never dlclose'd: a registered provider outlives the
 * call and protoCore's registry holds it.
 */
#pragma once
#include "protoCore.h"

#include <string>
#include <vector>

namespace protoScala {

inline constexpr const char* kProviderPluginABI = "protoScala-provider-1";

// Loads every discoverable plug-in. Returns the paths actually loaded, in load
// order, for --version and for the diagnostics. A plug-in that fails to load,
// exports the wrong ABI or returns non-zero is reported on stderr and skipped:
// a broken plug-in must never stop the runtime from starting.
std::vector<std::string> loadProviderPlugins(proto::ProtoContext* ctx);

} // namespace protoScala
```

- [ ] **Step 1: Implement discovery and loading**

```cpp
std::vector<std::string> loadProviderPlugins(proto::ProtoContext* ctx) {
    std::vector<std::string> loaded;
    for (const std::string& path : discoverPluginPaths()) {
        void* handle = ::dlopen(path.c_str(), RTLD_NOW | RTLD_GLOBAL);
        if (!handle) {
            std::fprintf(stderr, "protoscala: provider plug-in %s: %s\n", path.c_str(), ::dlerror());
            continue;
        }
        auto abi = reinterpret_cast<const char* (*)()>(::dlsym(handle, "protoScalaProviderABI"));
        auto reg = reinterpret_cast<int (*)(proto::ProtoSpace*)>(
            ::dlsym(handle, "protoScalaRegisterProviders"));
        if (!abi || !reg || std::string(abi()) != kProviderPluginABI) {
            std::fprintf(stderr,
                         "protoscala: provider plug-in %s does not export the %s ABI; skipped\n",
                         path.c_str(), kProviderPluginABI);
            continue;
        }
        // A plug-in runs foreign code. The mandatory boundary shape applies here
        // as much as at a call (plan A0-7): a C++ exception escaping dlopen'd
        // code into this frame would cross an ABI this binary did not compile.
        int rc = 1;
        try {
            rc = translateForeignException([&] { return reg(ctx->space); });
        } catch (const ScalaError& e) {
            std::fprintf(stderr, "protoscala: provider plug-in %s failed: %s\n", path.c_str(),
                         e.what());
            continue;
        }
        if (rc != 0) {
            std::fprintf(stderr, "protoscala: provider plug-in %s returned %d; skipped\n",
                         path.c_str(), rc);
            continue;
        }
        loaded.push_back(path);
    }
    return loaded;
}
```

`discoverPluginPaths` walks `PROTOSCALA_PROVIDERS` then `<dir of argv[0]>/../lib/protoscala/providers/` (computed from `/proc/self/exe` on Linux, falling back to `CMAKE_INSTALL_FULL_LIBDIR` baked in at configure time), taking `*.so` files in sorted order so the load order is reproducible. `translateForeignException` is Task 7's template; its return type is `decltype(call())`, so it instantiates for `int` here and for `const proto::ProtoObject*` at the other three sites with no second overload.

```cpp
 * A TEST DOUBLE, not a runtime. It registers a provider under the family alias
 * `js` so the `js.` prefix has something to route to, and it answers exactly
 * two logical paths with hand-built objects. It is built only by the test

 * are named for the stand-in rather than for a real library. A test double
 * answering as if it were numpy would be a green test asserting numpy
 * behaviour against a stub, which is the failure mode this family already
 * learned to reject (plan A0-12).

#include "umd/ProviderPlugins.h"

namespace {

// __probe.echo(a, b = <value>) -> "echo a=<a> b=<b>", so a fixture can show that
// a named argument crossed a REAL UMD boundary and arrived in the callee's
// keywordParameters. The key is the ADDRESS of the interned parameter-name
// symbol (INTEROP §7): createSymbol, never fromUTF8String.
const proto::ProtoObject* probe_echo(proto::ProtoContext* ctx, const proto::ProtoObject*,
                                      const proto::ParentLink*,
                                      const proto::ProtoList* positional,
                                      const proto::ProtoSparseList* keywords) {
    std::string out = "echo";
    if (positional && positional->getCount(ctx) > 0)
        out += " a=" + describe(ctx, positional->getAt(ctx, 0));
    // The key is the ADDRESS of the interned symbol, so look it up with the
    // address createSymbol returns and nothing else. fromUTF8String would work
    // by accident for "b" (short enough to embed in the pointer word) and fail
    // for a long name, which is exactly the trap INTEROP §7 documents.
    const auto* bKey = proto::ProtoString::createSymbol(ctx, "b");
    if (keywords) {
        const proto::ProtoObject* v =
            keywords->getAt(ctx, reinterpret_cast<std::uintptr_t>(bKey));
        if (v && v != PROTO_NONE) out += " b=" + describe(ctx, v);
    }
    const auto* longKey = proto::ProtoString::createSymbol(ctx, "aVeryLongKeywordName");
    if (keywords) {
        const proto::ProtoObject* v =
            keywords->getAt(ctx, reinterpret_cast<std::uintptr_t>(longKey));
        if (v && v != PROTO_NONE) out += " b=" + describe(ctx, v);
    }
    return ctx->fromUTF8String(out.c_str())->asObject(ctx);
}

        mod->setAttribute(ctx, proto::ProtoString::createSymbol(ctx, "name"),

    }
    const std::string& getGUID() const override { return guid_; }
    const std::string& getAlias() const override { return alias_; }
private:

};

}  // namespace
```

```cpp
/*
 * translateForeignException — the mandatory boundary shape (ROADMAP Phase 6,
 * protoST's exceptions spec §6). Every call that leaves protoScala for a UMD
 * provider or a foreign callable goes through it.
 *
 * THE CATCH ORDER IS LOAD-BEARING, clause by clause:
 *
 *  - FutureYield is NOT a std::exception and must be first anyway: a later
 *    catch(...) would eat a cooperative suspension and the actor would never
 *    resume.
 *  - ScalaThrow IS a std::exception (and deliberately not a std::runtime_error).
 *    Without this clause the std::exception arm would rewrite every Scala
 *    exception crossing a module boundary into a RuntimeException, losing its
 *    class and its payload.
 *  - ScalaError is already a translation; re-translating it would replace a
 *    precise class name with RuntimeException.
 *  - std::logic_error must NOT be translated and must NOT be catchable (D74):
 *    a compiler or VM defect must never be maskable by `catch { case e:
 *    Throwable => }`. It is re-thrown BEFORE the std::exception arm, which
 *    would otherwise catch it — std::logic_error derives from std::exception.
 *  - std::exception carries what() across.
 *  - catch(...) is the last resort and says so rather than inventing a message.
 */
#pragma once
#include "runtime/Errors.h"
#include "runtime/FutureYield.h"

#include <stdexcept>
#include <utility>

namespace protoScala {

template <typename Call>
auto translateForeignException(Call&& call) -> decltype(call()) {
    try {
        return call();
    }
    catch (FutureYield&)               { throw; }
    catch (ScalaThrow&)                { throw; }
    catch (ScalaError&)                { throw; }
    catch (const std::logic_error&)    { throw; }   // D74: a VM defect stays uncatchable
    catch (const std::exception& e)    { throw ScalaError("RuntimeException", e.what()); }
    catch (...)                        { throw ScalaError("RuntimeException", "native exception"); }
}

} // namespace protoScala
```

## Task 0 triage: what needs the maintainer, and what was decided on cost

The maintainer's standing rule, 2026-09-23: *"En la medida que sea razonable, least surprise para el programador. Por otro lado, si alguien escribe usando esos detalles está jugando con fuego y no creo que sea tan común."* — **follow Scala by default, bounded by proportionality: where matching is cheap, match it; where matching would cost real machinery and only unusual code could notice, document the divergence with a `D<n>`, a fixture showing both answers and a one-line cost justification.** And the second standing rule, from the same session: **the platform is late-binding even where Scala is not** — late *detection* is accepted, silent failure never is.

Escalation is reserved for what genuinely needs a maintainer: a contradiction inside DESIGN or between the documents; a change to a public surface or to a protoCore convention; anything touching the GC or the threading protocol; and anything where following Scala would cost machinery that a **common** usage depends on. Three items qualify. Everything else below is decided, with the cost that decided it.

### Decided on cost, recorded for review

Each is implemented as stated and recorded in `docs/DECISIONS-LOG.md` as "agent, decided on cost", with the cost that decided it. **None needs a reply.**

| # | Divergence or choice | Decision, and the cost that decided it |
|---|---|---|
| C1 | When an import is resolved (A0-1) | **Compile time, through a `ModuleLoader` seam.** The late-bound alternative is smaller — two natives, no seam — and it costs the programmer imported **types**: `new Point(1, 2)`, `case p: Point` and `case Point(x, y)` would not compile, and importing types is what a Scala programmer does with `import`. Following Scala costs a seam; not following it costs a common usage, so the seam is paid. It does not breach DESIGN §3.3: the loader returns plain C++ descriptors |
| C2 | What a module *is* (A0-2) | **An `object`.** Phase 4's nested-template lifting already gives qualified names, companions, sibling qualification and simple-name display — every mechanism a module needs. A bespoke module object model would be a second object model for something the first expresses, which is the reasoning that kept `enum` in the frontend. Cost: a module's name is its file name and it may not carry `@main` (**D91**) |
| C3 | When a module's top level runs (A0-3) | **At import.** Scala has no file-level modules, so nothing is diverged from; Python and JavaScript both run a module at import, and lazy initialisation would silently skip a module imported for its effects. Cost: **D90**, plus **D95** (`--disassemble` runs them too, because a file cannot be compiled without its imports) |
| C4 | Prefix routing by a **closed** four-name list (A0-4) | **Closed.** "Any registered alias is a prefix" is one line shorter and makes `import util.Strings` hijackable by a plug-in aliased `util` — a program's meaning must not depend on which plug-ins are installed. Cost: a fifth runtime needs one line in `src/umd/Prefixes.h`, which is a deliberate, reviewable edit |
| C5 | Prefixed imports bypass `getImportModule` (A0-4) | **Bypass.** protoCore's `SharedModuleCache` is keyed by logical path with **no `ProtoSpace` component** and is never invalidated (`core/ModuleCache.cpp`), so in the two-runtime process Task 10 creates a cached module could be handed to whichever runtime asked second. Calling `tryLoad` directly keeps each prefix bound to the provider its name selects. The unprefixed path still uses the chain, and Task 4 Step 6 records the residual hazard under R5 rather than pretending it away. Cost: a foreign module is cached by protoScala instead of by protoCore, which is nine lines in `loadForeign` |
| C6 | The resolution chain is **prepended to**, not replaced (A0-5) | **Prepend.** protoPython prepends and protoST replaces; replacing silently deletes another runtime's chain entries in a shared process, and the failure would look like "module not found". Cost: none |
| C7 | The module-path-versus-member rule (A0-6) | **Longest dotted prefix first, walking down, and the error names every path tried.** The alternative — require a brace selector for a member — is simpler and rejects `import a.b.C` where `C` is a member of `a.b`, which is ordinary Scala. | C8 | An `import` is hoisted to its unit (A0-6) | **Hoisted** (**D96**). Lexical scoping needs a scope-aware name resolver the compiler does not have, and D82's extensions have exactly the same shape — so the two are scoped together or not at all, which is what makes E6 one question instead of two. Cost: an import written inside a `def` is visible for the whole file, which accepts strictly more programs than Scala |
| C9 | A wildcard import of a foreign module is refused (A0-4) | **Refuse** (**D92**). The message names the working spelling, which is the bar D81 set. Cost: `import py.numpy.*` needs rewriting as `import py.numpy.{a, b}` |
| C10 | The boundary catch shape and its order (A0-7) | **One template, six clauses, the order ROADMAP prescribes plus a `std::logic_error` re-throw.** Each clause is one line and each prevents a specific silent failure: `FutureYield` eaten by `catch (...)`; a `ScalaThrow` rewritten into `RuntimeException`; a `ScalaError`'s class name replaced; and — the one ROADMAP's list does not mention — a VM defect made catchable, because `std::logic_error` **is** a `std::exception` and D74 says it must never be maskable. Statically linking every sibling runtime would multiply the binary and the start-up work this phase exists to reduce, make every runtime co-resident by construction rather than by decision, and make protoScala's build depend on five repositories. protoScala ships **no** plug-in; the only one built is the test double, and it is built by the test target |
| C12 | The stand-in provider registers under `js`, not `py` (A0-12) | **`js`.** It needs one of the four family aliases to exercise the routing, and protoJS registers none, so nothing is shadowed. Its fixtures are named `stand-in-provider-*` and it answers `probe`, never a real library's data. Cost: `import js.probe` in a fixture reads oddly until the comment above it is read, which is the price of not writing a fixture that lies |
| C13 | No opcode is allocated (A0-8) | **None.** The lowest free opcode is 40 and stays free: an import binds a name at compile time to a global that already exists, so the import site emits nothing. An `IMPORT_MODULE` opcode would add a run-time resolution the loader has already performed and a second way to reach a module. Task 13 Step 3 writes the absence into STATUS so a reader does not look for it |
| C14 | The prelude image is a **build product** (A0-9) | **Generated by `add_custom_command` with `DEPENDS lib/prelude.scala`.** A user-writable cache would need an mtime or a hash check at every start-up and could be poisoned; a build product cannot go stale, and the two guards (format version, source hash) exist only to catch a hand-copied file — and they *fall back* rather than fail, so the binary is always correct and at worst slower. Cross-compilation is guarded and simply takes the source path |
| C15 | The image emits **tables plus fixed reconstruction code**, not a blob (A0-9) | **Tables.** A serialised blob needs a deserialiser, which is the same surface plus a parser, and `MAKE_FN` carries a **module address** in a `SmallInteger`, so a blob could never contain one anyway. The reconstruction replays `addInt`/`addString`/`addSendSite`/… in the compiler's original order so the constant-pool indices come out identical — an invariant that is silent if broken, which is why Task 2 Step 6 compares `disassemble()` output rather than trusting it |
| C16 | `ImportError` is one new prelude class (A0-14) | **Add it.** A failed import must be a catchable `Throwable` whose name says what failed. Scala has no `ImportError`, so nothing is diverged from. Cost: one prelude class, about 60 µs of start-up at 0.5.0's rate, which Task 2's image absorbs |
| C17 | A module is compiled from the **post-prelude** `GlobalTable` snapshot (A0-16) | **A copy of `preludeGlobals_`.** The module must see the prelude (it needs `List`, `Option`, `println`) and must not see the importing session's names. | C18 | Task 10 may legitimately fail (Task 10 Step 3) | **A red test with a recorded diagnosis is the deliverable.** R5 has been open since Phase 0 and has never been exercised; the two acceptable outcomes are "it passed, recorded" and "it failed, with the exact failure recorded". **Gaps found while reviewing this plan, and closed inline:**

- **ROADMAP's first hand-off is not implementable, and the reason is not the one ROADMAP gives.** Found by reading protoPython's four `registerProvider` calls and their aliases, not by trying. Closed by A0-12, E7 and Track Y, with the two fixtures kept `XFAIL` and their directive corrected — and with an explicit prohibition on making them green with a stub.
- **`catch (const std::exception&)` in the boundary template would have made every VM defect catchable**, silently retiring D74, because `std::logic_error` derives from `std::exception` and ROADMAP's prescribed five clauses do not mention it. Closed by a `std::logic_error` re-throw **before** the `std::exception` arm, a unit test, and a `! grep` clause in Task 7's done-when.
- **A late-bound import would have made imported classes unusable as types.** Found by tracing what `NEW`, `TEST_PROTO` and `CompilePatterns` need — a `ClassInfo` the compiler holds. Closed by A0-1's compile-time seam, at the price of D90 and D95, both recorded.
- **A module compiled with a fresh `GlobalTable` would have collided with session globals.** `GlobalTable`'s key counters are shared by *copies* only, so a fresh table starts its counters at zero and hands out the bare name `trim` a second time. Closed by A0-16: a module is compiled from a **copy** of the post-prelude snapshot, which shares the counters and therefore the D25 shadowing machinery.
- **Prefixed imports going through `getImportModule` would have shared a cache keyed by logical path with no space component.** Found by reading `core/ModuleCache.cpp`, which keeps a function-local `std::map<std::string, const ProtoObject*>` with no invalidation. Closed by C5 (call `tryLoad` directly) and by recording the residual hazard for the unprefixed path under R5 rather than hiding it.
- **Replacing the resolution chain would have deleted protoST's entry in Task 10's process.** protoST replaces, protoPython prepends. Closed by C6 (prepend), which is also why Task 10 constructs the `STRuntime` first and the failure mode it would otherwise have had is named in the test's comment.
- **A `tryLoad` that raised for "not mine" would have broken the chain for every other provider.** `core/ModuleResolver.cpp:99` treats `nullptr` and `PROTO_NONE` as a miss and walks on. Closed by A0-5 and by the two fixtures of Task 4 Step 5, which pin the miss and the failure as *different* outcomes.
- **A second `Session` would have registered a second provider and left the first unreachable.** `registerProvider` indexes by alias with last-registration-winning while keeping every provider object alive. Closed by `std::call_once` (protoST's own guard) and by `ScalaModuleProvider.IsRegisteredExactlyOncePerProcess`.
- **A thread-local host pointer would have made every actor worker report "module not found".** Not guessed — protoST's `STModuleProvider.h` records having had exactly that bug. Closed by copying the `ProtoSpace`-keyed registry, including the intentionally leaked containers and the reason for them.
- **The image's constant-pool and block indices are a silent invariant.** `MAKE_FN`'s operand is a block index and every constant reference is a pool index, both baked into the emitted code words. An image that assigns pool slots directly instead of replaying the `add*` calls would produce a prelude that runs and is wrong. Closed by C15 and by comparing `disassemble()` output between the two paths.
- **A user-writable prelude cache would have needed an invalidation story and would still have been poisonable.** Closed by C14: the image is a build product, so invalidation is CMake's `DEPENDS`; the two run-time guards exist only for a hand-copied file and they **fall back** instead of failing.
- **`protoscala-precompile` cannot link `protoscala_runtime`**, but it needs the same builtin-global name list the runtime declares, which lives in `src/runtime/Primitives.cpp`. Two copies of that list would disagree eventually and the symptom would be a `Not found` at the user's first line. Closed by Task 2 Step 2 moving the **list of names** (strings only, no `ProtoObject*`) into `src/support/BuiltinNames.cpp`, which both sides call.
- **Task 1's decision rule is stated before the measurement exists**, so the branch cannot be rationalised after the fact. That is deliberate: the same discipline that makes a benchmark self-report.
- **`benchmarks/cold-start.sh` is not a CTest case and must not become one.** Timing on a shared host would make the suite flaky, and a flaky budget check is worse than a manual one. Closed by design note 14 and by making the script the done-when command rather than a test.
- **The worked example had no definition anywhere.** ROADMAP names it and nothing says what it is. Closed by Task 12 Step 3, which defines it concretely (`examples/log-report/`, three files plus a committed input, one deterministic final line, registered in `tests/cli/examples.sh`) so it is testable rather than decorative.
- **Chapter 15's subject was also undefined.** `docs/TUTORIAL.md` lists 14 chapters and says the missing one is "modules and polyglot imports, whose chapter is written together with the phase that implements them" — this phase. Closed by Task 12 Step 2's eight-section outline, with the worked example as an **unnumbered** row so the count stays at ROADMAP's 15.
- **`build_pkg/` is untracked and not ignored**, which is why `git status` is not clean on `main` and why Task 13's done-when has to exclude it by name. Closed by Task 11 Step 4.

**Ordering constraints:**

1. **Tasks 1 and 2 are independent of everything else** and should run first: they touch `Prelude.cpp`, CMake and a new tool, and nothing else in the phase reads them. Running them first also means every later task's suite run exercises the image path.
2. **Task 3 must precede Tasks 4, 5 and 6**: they implement `ModuleHost`, `loadForeign` and the plug-in loader against interfaces Task 3 declares.
